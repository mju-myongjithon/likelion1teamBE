# 1. 서비스 소개

**띵춘**은 인문캠·자연캠에 흩어진 학교 정보를 AI로 모아, 몰라서 놓쳤던 기회까지 쉽게 발견하게 해주는 서비스입니다. 발견한 정보를 매개로 캠퍼스 무관 번개·모임 모집이 자연스럽게 이어지고, 나아가 대회·공모전 팀원 모집까지 연결되어 정보에서 교류와 협업으로 확장됩니다.


- **정보 파편화 해소**: 15개 이상 흩어진 학교 공지·행사·공모전 정보를 AI가 수집·요약해 하나의 캘린더로 통합합니다.

- **자연스러운 캠퍼스 교류**: 캠퍼스 무관 모집 게시판을 통해 정보 발견이 실제 만남으로 이어집니다. 

- **협업으로의 확장**: 대회·공모전 팀원 모집까지 연결해 일회성 교류를 넘어선 협업 기회 제공합니다.

# 2. WHY? 

**"같은 학교인데, 왜 서로 다른 캠퍼스를 이렇게까지 모를까?"**

명지대는 인문캠과 자연캠, 두 캠퍼스로 나뉘어 있습니다. 물리적으로 멀리 떨어진 것도 문제지만, 저희가 직접 조사하면서 발견한 진짜 문제는 따로 있었습니다.
**정보가 없는 게 아니라, 흩어져 있어서 안 보이는 것.**

학교 공지·행사·공모전은 15개가 넘는 부서·단과대 사이트에 각각 흩어져 있고
그마저도 대부분의 정보는 인스타그램으로 접하는데, 이것마저 인문캠 학생회·자연캠 학생회 계정이 따로 분리되어 있어 상대 캠퍼스 소식은 팔로우하지 않으면 알 방법이 없습니다.

심지어 같은 캠퍼스 안에서도, 옆 학과가 어떤 대회·전시·행사를 하고 있는지조차 모릅니다. 실제로 저희 팀원의 지인은 지원자가 적었던 교내 필름카메라 대회에서 쉽게 수상한 경험이 있었는데, 이건 정보가 없어서가 아니라 "존재하는지조차 몰라서" 생긴 기회였습니다

즉 **문제는 캠퍼스 간 거리가 아니라, 정보 자체가 원래부터 파편화되어 있다는 것이었습니다.**
그래서 저희는 "사람을 모으는 서비스"보다 먼저, "**정보를 모으는 서비스**"가 필요하다고 판단했습니다.
띵춘은 이 파편화된 정보를 AI로 모아, 몰랐던 기회를 발견하게 하고 — 그 발견이 자연스럽게 캠퍼스와 학과를 넘나드는 만남으로 이어지게 만드는 서비스입니다.

# 3. :computer: 핵심 기능

### 회원가입 / 인증
- 학교 이메일(`@mju.ac.kr`) 인증번호 발송 및 확인 (Gmail SMTP 실제 메일 발송)
- 인증 완료 후 소속 정보(과정·캠퍼스·단과대학·학과·학번) 등록
- 관심 태그(9종, 3개 이상) 선택 및 저장

### 마이페이지
- 내 프로필(이름/학과/캠퍼스/관심 태그) 및 활동 통계(내가 쓴 글 수, 참여한 모임 수) 조회
- 내가 쓴 모집글 + 신청한 모집글을 활동 목록 하나로 통합해서 최신순으로 확인
- 신청 상태(신청대기중 / 참여확정 / 거절) 실시간 확인

### 모집글 / 참여 신청
- 프로젝트·학교행사·공모전·스터디 등 카테고리별 모집글 작성 및 상세 조회
- 모집글 참여 신청, 작성자의 신청자 목록 조회 및 수락/거절 처리
- 수락 시 모집 인원 자동 반영, 정원 도달 시 자동 마감

### 검색
- 모집글과 학교 공지사항을 키워드 하나로 통합 검색

### 학교 공지 크롤링 & AI 태깅
- 명지대학교 홈페이지 공지사항을 주기적으로 자동 크롤링
- Gemini API 기반으로 크롤링된 공지에 자동 태깅

# 4. :department_store: 프로젝트 구조
도메인 단위 패키지 구조로 구성되어 있습니다.

```
com.lionking.ddingchun
├── auth        # 이메일 인증
├── user        # 회원가입, 마이페이지
├── post        # 모집글
├── application # 모집글 참여 신청/수락
├── search      # 통합 검색
├── crawler     # 학교 공지 크롤링, AI 태깅
└── global      # 공통 응답/예외 처리, 설정
```

각 도메인은 `controller` / `service` / `repository` / `entity` / `dto` / `exception`으로 나뉘며, 예외는 전부 `BusinessException`을 상속해 `GlobalExceptionHandler`에서 공통으로 처리합니다.

# 6. :rocket: 실행 방법

1. `.env.example`을 참고해 `.env` 파일 생성 (DB 계정, Gmail 앱 비밀번호 등)
2. `docker-compose up -d`로 로컬 PostgreSQL 실행
3. `./gradlew bootRun`으로 서버 실행 (기본 포트 8080, context-path `/api`)
4. `http://localhost:8080/api/swagger-ui/index.html`에서 API 문서 확인
